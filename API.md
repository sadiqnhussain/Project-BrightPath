# REST API v1 notes

Base path: `/api/v1/`. Current endpoints use Django session authentication. For browser `POST`, `PUT`, and `PATCH` requests, send the CSRF token. The future native mobile client must use a separately designed token authentication flow; do not send passwords on every request or add Basic Authentication.

All endpoints require authentication unless otherwise stated. JSON errors use DRF's standard response format. The API intentionally returns only the data needed for the current client.

## Identity and school context

### `GET /api/v1/me/`

Returns the authenticated account, account type, active/pending memberships and student class profile where applicable.

### `GET /api/v1/institution/classes/`

Returns classes for the active institution. Owners/admins can see all classes; teachers see only classes assigned to them. If the adult account belongs to multiple institutions, pass `?institution=<membership-id>` (institution database ID) to select the authorized context.

## Student learning

### `GET /api/v1/student/courses/`

Returns only published courses that the student is authorized to access through an active class or individual assignment, within the availability window, with matching grade eligibility.

### `GET /api/v1/courses/{course_id}/`

Students can retrieve only assigned courses. Authorized staff can retrieve courses inside the institution context they belong to.

### `GET /api/v1/lessons/{lesson_id}/`

Student responses omit correct answer indexes and explanations. Staff responses require an active staff membership in the course's institution.

### `PUT /api/v1/lessons/{lesson_id}/progress/`

Example body:

```json
{ "percent": 40, "last_position": 120 }
```

Progress is capped below 100 through this endpoint; completion is recorded by completing a lesson or submitting the quiz.

### `POST /api/v1/lessons/{lesson_id}/quiz/`

Example body:

```json
{ "answers": { "17": 0, "18": 2 } }
```

Question IDs map to zero-based choice indexes. The server validates indexes, calculates scores, records the attempt, completes progress and grants an idempotent reward event. The response includes the score and feedback after submission.

### `GET /api/v1/progress/`

Returns the student's own progress, a verified guardian's linked-child progress, or authorized institution progress for staff. For staff with multiple institution memberships, select `?institution=<id>`.

## Guardian access

### `GET /api/v1/guardian/children/`

Returns summaries only for active students whose guardian link is explicitly verified and consented and whose institution is active.

## API security invariants

- A client-provided institution ID is a selector, not proof of authorization; every query still checks membership.
- Student course and lesson access is revalidated server-side on each request.
- Correct answers are never returned before submission.
- The client cannot directly write reward balances.
- The mobile client must not receive broad administrative access merely because it can call an API endpoint.

## Interactive API documentation

With the application running, the generated OpenAPI schema is available at `/api/schema/`.
Use `/api/docs/` for Swagger UI or `/api/redoc/` for ReDoc. The schema is generated by
`drf-spectacular`; API view descriptions can be expanded with `@extend_schema` annotations as
endpoints evolve.
